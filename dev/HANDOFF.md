## 1. 프로젝트 목표와 개발 원칙

**사용자**: 비개발자. 훨훨 '입지센스 마스터 패키지' 강의로 갈아타기를 공부하는 직장인. 설명은 쉬운 말로, 결론 먼저, 한국어.

**최종 목표(북극성)**: 아실을 벤치마킹한 앱 "비상한 아파트"(가제, 브랜드 후보: 아파트 비상 / 아파트 훨훨, 캐치프레이즈 후보: 날아갈 내 집 찾기).
핵심 가치 = "내 자본 + 규제·대출 한도 → 내가 갈 수 있는 서울 생활권과 아파트 추천". 웹사이트 → PWA → 앱 → 브랜딩·광고 순. 같이 공부하는 사람들에게 공유할 예정이라 누구나 이해할 수 있어야 함.

**개발 원칙**
1. v1(`docs/v1`, 브랜치 `v1`)은 절대 수정 금지. 정식 사이트 반영은 사용자가 "정식 반영"이라고 말할 때만.
2. 새 기능은 무조건 `/beta/`(`docs/beta`)에서 먼저.
3. 기능을 늘리기보다 이해하기 쉽게: 버튼을 늘리지 말고 그래프 표시·주석·ⓘ 설명으로 구분. 새 탭·버튼이 필요하면 먼저 물어봄.
4. 휴대폰 화면(390px)이 기준. 숫자 왼쪽 정렬, 칸 너비 같게, 요약표는 최근 거래·기간 최고를 앞에.
5. 평 변환 표시 안 함(전용면적 유지). 튀는 거래 표시 기능 안 넣음.
6. 자동화 전제: 수동 입력 데이터도 data/ 아래 JSON으로 분리, `출처`·`기준일` 칸 포함. 월 1회 GitHub Actions 자동 갱신 구조 유지.
7. 모든 숫자에 ⓘ로 기준(기간·건수·계산식). 화면 하단에 "참고용, 투자 권유 아님".
8. 정책·규제는 평가·예측 없이 날짜와 사실만.
9. 사용자가 입력하는 자본·대출 정보는 브라우저(localStorage)에만 저장, 외부로 보내지 않음.
10. 버그는 원인부터 보고. 바뀐 부분만 수정(이미 있는 파일 통째 재작성 금지). `docs/data/` 자료 형식은 바꾸지 않음(새 기능 자료는 새 파일로).
11. 모르는 데이터(API 키, 강의 PDF 내용, 대출·규제 수치)는 추측하지 말고 요청.
12. 시세 요약 파일(`summary/`) 항목 이름을 바꿀 때는 먼저 보고(별도 '임장기록' 프로젝트가 읽음).

## 3. Phase 0~4에서 한 일과 확정된 결정

### Phase 0 (점검)
- 지도 숫자 앞 "-"는 애니메이션 버그(진행률 음수) → Phase 1에서 애니메이션 자체를 없앰.
- 지도 경계 2013년 자료는 지금 25개 구와 일치(구 이름 매칭).

### Phase 1 (홈 지도 마감·연결·자동 갱신)
- **숫자 애니메이션 없음**: 처음부터 최종값만 표시(외부에서 읽어도 맞는 값).
- **잠정 월**: 자료의 **마지막 달만 "잠정"**. 대표 숫자는 그 직전 달(확정월) 기준. ⓘ에 "마지막 달은 신고기한(30일)이 남아 거래가 덜 들어옴".
- 생활권 화면 주소 바로가기, 지도 구 상세 생활권 목록 → 생활권 그래프, 링크 복사 버튼.
- **정식 사이트 링크는 각 화면 맨 아래 안내 줄**("정식 사이트 →"), 메뉴는 5칸 유지.
- **생활권 101개 그대로 유지**(22개 구 4개씩 + 은평 5 + 강남 5 + 금천 3).
- 시험판 자료 월간 자동 갱신(`beta.yml`) 연결. 안 쓰던 `beta/data/group/`, `scripts/build_group.js` 삭제.

### Phase 2 (데이터 기반 정리)
- **단지 마스터** `docs/beta/data/master/complexes.json` (생활권 대표 단지 499곳)
  - **ID 규칙**: K-apt 단지코드(여러 K-apt가 붙으면 세대수 큰 코드). 없으면 `R-{구코드}-{정리한 단지명}`. 서로 다른 단지가 같은 코드면 이름이 더 비슷한 쪽만 코드, 나머지는 규칙 ID. 점수가 같으면 공동 등록으로 보고 `코드-2` 식으로 구분(압구정현대1·2차/6·7차, 돈암한진/한신, e편한서울대입구1차/2차) — 이 경우 세대수는 합계뿐이라 비워 둠.
  - 연결: 생활권 → 실거래(lifezones 이름 규칙) → K-apt(같은 법정동, 이름 비교, 숫자(차·단지) 다르면 연결 안 함) → 정비사업(같은 동 구역 이름, 숫자 다르면 안 함).
  - 세대수: 생활권 설정(강의자료) → 없으면 K-apt 합계. `세대수출처` 칸에 표시.
  - 손으로 고칠 곳: `data/master/overrides.json` ("구|단지명": {kapt:[…], 세대수, _근거}). 지금 4곳(중랑숲리가, 우이성원상떼빌, 불광라이프미성, 박석고개힐스테이트1단지).
- **정비사업 자동 수집**: 서울 열린데이터 OA-22856에는 Open API가 없음 → 사이트 내려받기 버튼과 같은 방식(`datafile.seoul.go.kr/.../nio_download.do`, frmFile 양식 + seq)으로 `scripts/fetch_jb.py`가 받음 → `data/jb_auto/`. `scripts/build_jb_beta.py`가 정식 `build_jb.py`를 고치지 않고 경로만 바꿔 실행 → `docs/beta/data/jb.js`. 시험판 생활권 화면은 이 파일을 읽음. (26.06 파일은 손으로 넣은 것과 바이트까지 같음 확인)
- **출처·기준일 통일**: 시험판 자료 파일마다 `출처`(배열)·`기준일`{자료, 갱신, …}·`만든곳`.
- **생활권 요약 자리**: `docs/beta/data/lz_summary.json`(101개 빈칸). 채우면 생활권 보기 맨 위에 2~3줄, 비면 숨김.
- 시세 요약 파일: 세대수 47곳 채움 + `출처`·`기준일`·`만든곳` 칸 추가. 세대수 순 정렬이라 31개 생활권에서 단지 번호 순서가 바뀜 → **그대로 두기로 결정**.

### Phase 3 (상승·하락)
- **전고점·전저점은 일반 매매만**(분양권·입주권 제외). 전고점 = 2021~22 최고가, 전저점 = 그 뒤 최저가(2건 이상이면 가장 낮은 1건은 급매로 보고 뺌). 시세 = 4층 이상 최근 12개월 중 최근 3건 중간값.
- **사이클 분류**(`cx.json`의 `사이클`):
  - 가능 → 돌파(시세 > 전고점) / 회복 중(회복률 40% 이상) / 바닥권(40% 미만)
  - 판단 불가(순위·회복률에서 뺌): `신축`(2021~22 일반 매매 2건 미만 + 분양권 있음 또는 2021년 이후 준공) · `신축입주권`(입주권 위주였지만 이미 준공 = **준공(사용승인) 연월 ≤ 자료 기준월**이거나 일반 매매 있음. 연월을 모르면 준공 연도 < 기준월 연도일 때만) · `거래부족`(구축인데 2건 미만, 또는 전고점 뒤 거래 없음) · `저≥고`
  - 정비사업 진행(`입주권`): 거래 절반 이상이 입주권이고 아직 준공 전 → 회색 태그로 목록 맨 아래, 누르면 생활권 정비사업 탭
  - 84㎡: 400 = 가능 311 + 판단 불가 81 + 정비사업 진행 8
- **하락기 = 서울 84㎡ 시세(25개 구 3개월 이동 중간값의 중간값)의 2021~22 전고점 달 ~ 그 뒤 전저점 달** = 현재 21.11~22.12. 구별로 잡으면 3~33개월로 들쭉날쭉해서 서울 기준 하나로 통일, 하드코딩 아님.
- `docs/beta/data/x/cycle.json`: 생활권별 단지 하락기 거래·낙폭·저점 뒤 상승률·회복률, 생활권 순위·평균, "하락기에도 잘 팔린 단지" 상위 3(거래 순위 + 낙폭 순위 합이 작은 순, 단지 2곳 이상일 때).
- 생활권 보기 탭에 "하락기에도 잘 팔린 단지" 카드(새 탭·버튼 없이), 상승·하락 화면에 단지 사이클 성적표(검색, 생활권 평균·서울 순위 비교).

### Phase 4 (내 집 진단)
- 내 집: 생활권 서열, 구 안 생활권 순위, 생활권 안 단지 순위, 서울 단지 순위, 같은 금액대 ±5% 다른 생활권 전체(내 생활권보다 높은 곳 보라색).
- 가고 싶은 집: 목표 단지 생활권 안·서울 순위, 지금 가격 차이, 가격 차이 추이 그래프(월별 중간값, 거래 없는 달은 앞 달 값).
- 저장: `silgeorae_mine_v1`, `silgeorae_target_v1` (localStorage, 이 기기만).

### 생활권 대표 단지 선정 방식 변경 (2026-11-27, 자양·구의 롯데캐슬 리버파크 시그니처 누락 발견 계기)

### Phase 3·4 마무리 (2026-11-27 결정)
- **정비사업 진행 분류 = 준공 연월 기준**: 입주권 위주 단지는 사용승인 연월 ≤ 자료 기준월이면 `신축입주권`(신축, 입주권 시절). 연월 출처 순서: `data/master/kapt_usedate.json`(K-apt 사용승인일 전체, `scripts/fetch_usedate_beta.py`가 beta.yml에서 받음 — 정식 `fetch_hh.py`는 연도만 저장하기 때문) → `data/master/usedate.json`(손 확인, 항목마다 기준·출처·확인일, `예정:true`는 분류에 안 씀). cx.json 단지에 `준공월`{연월, 출처} 칸 추가.
- 확인 결과(기준월 26.11): 잠실래미안아이파크 25.12 · 잠실르엘 26.01 · 롯데캐슬하이루체 26.04 · 강변역센트럴아이파크 26.09 · 디에이치방배 26.09 · 힐스테이트메디알레 26.10 → 모두 신축(입주권 시절). 장위6(27년 예정)·연희1(29.01 예정)만 정비사업 진행. K-apt 캐시는 연도만 있어 월은 입주 시작 기사·입주 안내로 확인(K-apt 연도와 모두 일치). 84㎡ 정비사업 진행 8 → 2.
- **상승률 정렬 버튼 안 넣음.**
- **"잘 팔린 단지"는 하락기 거래 건수 기준 유지**, 세대수 대비 회전율(하락기 거래 ÷ 전체 세대수 ×100, %)을 보조 숫자로만 표시(순서에 안 씀). cycle.json 단지에 `회전율` 칸.

### Phase 5 (자본 계산기 → 생활권 추천, 2026-11-27)
- **규칙 파일** `docs/beta/data/rules.json`(화면 기준 경로 `data/rules.json`, 기준일 2026-11-27). 값은 사용자가 준 그대로, 항목마다 `출처`·`확인일`. 배열 항목(주담대 캡·중개보수)은 `구간` 칸으로 감쌈. 화면·계산은 이 파일에서만 값을 읽음(취득세 6~9억 식 "(가격억×2/3−3)%", 지방교육세 "본세×10%"도 글자 그대로 읽어 계산). 규제 해제·변경 시 이 파일만 수정.
- **계산** `docs/beta/cap.js`(화면·검증 공용, 단위 억): 가격 P를 0.1억씩 100억까지 전부 스캔. 대출 = min(LTV×P, 주담대 캡(P ≤ 상한가인 첫 구간), DSR 한도, 월 상환 한도). DSR 한도 = (연소득×40% − 기타 연상환) ÷ 12 × 원리금균등 계수(금리+스트레스 3%, 30년). 월 상환 한도는 스트레스 없이 금리 가정으로. 필요 현금 = P − 대출 + 취득세(본세+교육세, 85㎡ 이하 가정이라 농특세 없음) + 중개보수(상한 요율). 필요 현금 ≤ 자본인 최대 P.
- **절벽**: 결과가 캡 경계(15·25억) 이하이고 바로 위(경계+0.1억)가 막히면, "한도 그대로였다면 어디까지"를 다시 계산해 더 갈 수 있었을 때만 주황 박스로 이유 표시. 한도를 정한 제약은 1줄(같으면 "LTV·캡"처럼 같이).
- 비교: 강의 공식 = 자본 ÷ (1 − 규제지역 LTV) = ÷0.6, 정밀 결과와 차이.
- **추천**: 매수 가능 가격 ±5% 시세(59·84㎡ 둘 다)의 생활권 대표 단지 → 생활권별로 묶어 생활권 상단(84㎡ 12개월 최고가, cx.json `대장`) 높은 순, 6곳 + 더 보기. 단지마다 하락기 거래·낙폭·저점 뒤 상승률(판단 불가면 이유). 가능 가격보다 비싼 단지(+5% 쪽)는 "가능 가격보다 X억 위"를 붙임(15억 절벽처럼 위가 막힌 경우 오해 방지). 정비사업 진행(입주권) 단지는 제외하고 "입주권은 별도 계산 예정" 안내.
- **입력**: 가용 자본(억)·부부 연소득(만원)·기타 대출 연상환액(만원)·감당 월 상환액(만원, 비우면 제한 없음)·금리(%, 비우면 rules 기본 4%). 기본값·예시값 없음, 자본과 연소득이 있어야 계산. 저장 `silgeorae_cap_v1`(localStorage). 새 탭·버튼 없음(입력하면 바로 계산).
- 화면 표시: "규칙 기준일", "참고용 · 최종 확인은 은행·세무사", 전세 끼고 매수 불가(토허 실거주 2년), 1주택 갈아타기 6개월 처분 조건. **일시적 2주택 취득세·양도세 비과세 판단은 하지 않음**(세무사 영역).
- 검증 예(연소득 3억·금리 4%): 자본 5억 → 7.9억(강의 8.3) · 9억 → 14.0억(15.0) · 10억 → 15.0억(16.7, **15억 절벽**: 15.1억은 현금 11.7억 필요) · 12억 → 15.3억(20.0, 캡 4억) · 20억 → 23.0억(33.3, 캡 4억). 연소득 8천만이면 9억 → 12.5억·10억 → 13.4억(DSR이 4.01억으로 막음).

### 그 밖에 확정된 것
- 시세 그룹: 생활권 서열 기준 2가지(대표 단지 중간값 / 대장 단지), 내 호가(`silgeorae_hoga_v1`), 네이버 호가는 링크만(자동 수집 안 함 — 약관·차단 문제).

- 잠정 표시·출처 칸 등은 시험판에만 있음(정식 미반영).
